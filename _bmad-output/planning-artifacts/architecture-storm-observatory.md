# Storm observatory architecture
Extend existing authenticated fetch Lambda with GET /storms/eowyn. API Gateway JWT route uses the existing integration and permissions. No new infrastructure stores or external service accounts.
Fetch configured station metadata plus two fixed <=3-day observation windows from api.weatherflow.com/swd/rest over HTTPS with explicit bucket=a. Existing TEMPEST_TOKEN stays in Lambda environment. Device must be present in configured station metadata; no user-controlled URLs/IDs/date ranges. Strict payload validation, finite numeric values, one-minute intervals; deduplicate timestamps and omit conflicting duplicates. Summarize interval rain, sampled gust maxima/temperature extrema and station pressure. Per-metric minute coverage; episodes stop at missing or invalid gust intervals. No interpolation.
Use a bounded module cache keyed to configured host/station/device/token, max one success for one hour, coalesce concurrent work, clear failures. Whole-operation deadline below API Gateway's timeout. Independent comparison failure leaves event usable with explanatory status. HTTP responses private/no-store. Never log upstream credential-bearing URLs or payloads.
Frontend Feature-Sliced Design: entities/storm contains public DTO/API plus curated public source evidence; widgets/storm-story owns presentation, navigation switches between story and unchanged trend shell. Static public evidence contains no station coordinates/readings. SVG schematic uses named regions, not precise storm track coordinates; text timeline is the equivalent accessible representation.
Source register in docs; operational failure/refresh/rollback guide; browser verification in mock mode distinct from production. Production verification uses authenticated route if existing identity is available, otherwise direct Lambda invocation via approved AWS workflow without publishing private observations.
